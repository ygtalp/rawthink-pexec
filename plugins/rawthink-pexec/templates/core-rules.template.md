## Violation tiers

`spec-verify` grades against these.

### BLOCKING — any one of these fails the spec

1. **Pseudocode** — every code block must be complete and compilable. No
   `...`, no `TODO`, no empty bodies, no code-as-table.
2. **Unverified API** — every referenced member must exist in source that
   spec-create actually read. Documentation is not a source.
3. **Wrong namespace/package** — verified from the real file, never assumed.
4. **Scope creep** — the plan's phase definition is the boundary. Narrowing is
   a question to ask; widening is a violation.
5. **Signature mismatch** — overrides and implementations must match their base.
6. **Reproduced lesson** — any L-code from the lessons file appearing again.

   invariants, regulatory constraints}}

## Spec file format

Every `phase-{N}-SPEC.md` contains these sections, in this order:

1. **Provenance** — plan items / findings this phase implements
2. **Depends on** — phases and their status
3. **Scope: IN** — files and symbols this phase may change
4. **Scope: OUT** — what it must not touch
5. **Blast Radius** — what a change here reaches
6. **File Summary** — table: file / action / namespace / why
7. **Task Breakdown** — per task: file, action, namespace, dependencies,
   COMPLETE implementation code
8. **Dependency Graph** — ordering between tasks
9. **Validation Criteria** — numbered, measurable
10. **Integration Checkpoints** — updated, or "NO CHANGES NEEDED" + rationale
11. **Open Questions** — must be EMPTY before implementation
12. **Rollback** — how to undo this phase

## Phase summary format

`summaries/phase-{N}-summary.md`, ~30 lines, built from REAL files:

```
# Phase {N} Summary — {name}

**Commit:** {hash}
**Status:** COMPLETE | PARTIAL ({K} incomplete)
**Build:** {compile result} | {test result}

## What changed (1 paragraph)

## Added/changed public API
- {signature} — {what it does}     (read from source, verify the signature)

## Added/changed {{schema | config | state}}
- {actual change, from the real file}

## Critical patterns / invariants
- {what later phases must not break}

## Decision Record
- decided / rejected / because / touches
  (ALWAYS — the archive is for cross-milestone recall; this is what the next
  phase actually reads)

## Note for the next phase
- {what phase N+1 can rely on}
```

**Build the summary from the changed files, not from the spec.** It is the
input to every later phase; copying the spec propagates the spec's errors
forward instead of catching them.
